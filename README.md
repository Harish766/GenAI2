## Problem and objective

Build English-to-French translation systems using an encoder-decoder Transformer trained from scratch, multilingual mT5 adapted for translation, and two decoder-only instruction models, Llama and Gemma. Compare them on the same saved test split using BLEU, chrF, wall-clock time, and parameter count. Review translation errors and responsible AI concerns.

## Dataset

The dataset is [OPUS Books, English-French](https://huggingface.co/datasets/Helsinki-NLP/opus_books), a public aligned literary-text corpus. Its dataset card reports 127,085 pairs in the English-French configuration. The experiment downloads `Helsinki-NLP/opus_books`, configuration `en-fr`, from Hugging Face Datasets. It normalizes Unicode to NFC, collapses whitespace, filters pairs to 3-35 English and 3-40 French whitespace-delimited words, removes duplicate pairs, shuffles with seed 42, and saves a 4,000/400/200 train/validation/test subset under `data/`. The same 200 test pairs are passed to every model. These files are generated by the script and remain local because of their size and the source dataset's licensing terms. **Do not replace the test split after seeing model outputs.**

## Models and adaptation

| System | Architecture | Adaptation |
|---|---|---|
| Basic Transformer | Two-layer PyTorch encoder-decoder, width 128, four attention heads | Trained from scratch on the 4,000 pairs; separate word and punctuation vocabularies |
| [mT5-small](https://huggingface.co/google/mt5-small) | Multilingual encoder-decoder | Rank-8 LoRA on attention query and value projections, two epochs in FP32 |
| [Llama 3.2 1B Instruct](https://huggingface.co/meta-llama/Llama-3.2-1B-Instruct) | Decoder-only | Zero-shot instruction prompt; no task-specific training |
| [Gemma 3 270M IT](https://huggingface.co/google/gemma-3-270m-it) | Decoder-only | Zero-shot instruction prompt; no task-specific training |

The small subset and model variants fit a deadline-limited experiment. This is **not** an architecture-only comparison: pretraining, size, tokenization, and adaptation methods differ. The [mT5 model card](https://huggingface.co/google/mt5-small) states that its base model needs downstream fine-tuning, so this project applies LoRA. FP16 caused NaN losses in the earlier mT5 run, so training and model loading now use FP32 with explicit finite-loss checks. mT5 generation suppresses sentinel tokens and repeated trigrams; causal-model generation avoids duplicate chat-template special tokens and retries an empty output with a plain prompt. These changes are evaluated on the saved test split; they do not imply a score before a successful run. Llama and Gemma weights can require license acceptance on Hugging Face.

The downloaded results archive contains only artifacts listed in the current `results/run_status.json`, plus the split manifest, script, and README.

2. If Llama or Gemma is gated and you want to run them after approval, visit the linked model pages and accept their licenses. Reuse an existing Hugging Face token by adding it to Colab Secrets as `HF_TOKEN`, or log in privately in a local terminal:


   The Colab notebook reads `HF_TOKEN` from Secrets if present and checks for an existing login. It does not request a new token. A login is unnecessary for Basic Transformer and mT5-small.    No manual dataset or model-weight download is needed. `datasets.load_dataset` and `transformers.from_pretrained` download the English-French corpus and accessible pretrained checkpoints into the runtime cache as needed. Pending-access checkpoints are not downloaded. Allow several gigabytes of disk space and a stable connection. The basic Transformer starts from random weights and has no external checkpoint.

3. Run the four-model workflow (inaccessible gated models are recorded as Not run):

   ```bash
   python experiment.py
   ```

   `--models basic mt5` runs selected models only; `--no-temperature-study` skips optional sampling. The final submission run uses the defaults: **4,000 train, 400 validation, and 200 test pairs**. Existing saved splits are reused and checked for size, overlap, and manifest consistency. Changing sample counts requires a separate fresh directory so the held-out test set is not silently replaced. A selected-model invocation reports only models completed in that invocation; older files remain on disk but are excluded from its report and archive.

4. Commit `experiment.py`, `requirements.txt`, `README.md`, and the generated `results/` files to GitHub. Model checkpoints and the source dataset are intentionally ignored by `.gitignore`; the saved metrics, translations, report, and temperature outputs are suitable for the repository. If the evaluator needs exact splits, include the generated `data/*.csv` only after checking the dataset license.

The run downloads the corpus, trains the first two models, and attempts 200 translations for each accessible model using greedy decoding and a 64-token cap. BLEU and chrF are computed by SacreBLEU only after output-quality checks and saved-artifact verification pass. Models with excessive empty outputs, sentinel tokens, non-finite losses, or invalid scores are marked Failed, with blank comparison values. The script saves the primary report and plots before attempting the optional temperature study on the first eight test items at 0.2, 0.7, and 1.0. A temperature-study error is recorded separately without changing a valid primary result. Models run sequentially to reduce peak memory use. Training and inference times use `time.perf_counter`; model download/loading time is excluded from inference time. All reported metrics are machine-generated from saved predictions.

**Results policy:** Scores appear only for models with saved, validated 200-item translation and metric files. The reconciled `results/run_status.json` identifies the backup and test-split hash; it is explicitly **not** a single experiment invocation. The original mT5-only run status is retained separately. The report keeps four model rows while plots use the three completed systems only. Failed mT5 has blank scores. A full four-model conclusion would require its own valid 200-item mT5 results on the same split.

BLEU measures matching word sequences; chrF measures character n-gram overlap. Neither alone proves the translation is accurate or safe. The report compares both quality scores and compute costs, and notes that mT5 and the basic Transformer are encoder-decoder systems while Llama and Gemma generate causally. Because the models differ in pretraining and adaptation, interpret any rank as a result for this setup, not a general conclusion about architectures.

## Sampling temperature analysis

The backup contains three valid eight-item temperature studies for Basic, Llama, and Gemma at 0.2, 0.7, and 1.0. mT5 has no temperature result because generation failed. The full report gives the recorded exploratory scores and explains why eight items cannot establish a stable temperature ranking.

The primary comparison is deterministic greedy decoding. The separate `*_temperature.json` outputs, when generated, sample eight shared examples at temperatures 0.2, 0.7, and 1.0 using `top_p=0.9` for pretrained models. Sampling runs **after** the primary report is saved, with finite-probability checks and invalid-logit handling. If it fails, `run_status.json` and the report record the failure, and no temperature score is claimed for that model. A sample of eight is too small for a robust ranking; higher temperature may increase variation and risk extra or omitted words. Identify the best measured model only among completed systems, and defer the four-way conclusion until all four systems have valid scores.

## Responsible and ethical use

Review `*_translations.jsonl` side by side for hallucinated additions, omissions, changes to names or numbers, gender or politeness bias, and cultural tone. Literary sentences may contain dated social assumptions. For sensitive material, obtain a human review, display the source sentence, preserve uncertainty and named entities, and avoid treating a single automatic score as a safety check. The generated report records these limits without inventing specific errors before seeing translations.
